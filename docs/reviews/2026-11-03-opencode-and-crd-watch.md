# OpenCode: петля поиска MCP и застывшие CRD-вкладки

## Подтверждённая причина поведения OpenCode

В конфиге управляемого workspace было `mcp.servers.kubiki.codemode=false`. Это помещало инструменты Kubiki в прямой каталог модели, но модель использовала `execute → search`, который работает с отдельным каталогом Code Mode. В исходниках OpenCode v2.0.27 эти наборы явно разделены. Поэтому поиск `pod`, `diagnose` и namespace `kubiki` не мог обнаружить эти инструменты через выбранный путь.

MCP при этом подключился: журнал для соответствующего workspace содержит `mcp connected`, `server=kubiki`, `tools=26` в 06:56:55 UTC (09:56:55 по Москве). Следовательно, это не доказательство отказа сокета или отсутствия Kubernetes backend. `list_mcp_resources` тоже не заменяет каталог tools: сервер Kubiki публикует инструменты, а не перечень объектов Kubernetes в MCP resources.

Ссылки на первичный код: [разделение каталогов](https://github.com/anomalyco/opencode/blob/v2.0.27/packages/core/src/tool.ts), [регистрация MCP](https://github.com/anomalyco/opencode/blob/v2.0.27/packages/core/src/tool/mcp.ts), [официальные настройки MCP](https://opencode.ai/v2/docs/mcp-servers).

Второй дефект — внешний kickoff обрезался регулярным выражением после `diagnosis, uncertainty`, вместе с требованиями к итоговому ответу. Третий — default_agent не задавался, поэтому новая сессия стартовала в Build.

Исправления:

- Kubiki регистрируется в Code Mode; весь разрешённый каталог остаётся доступен через namespace, без списка избранных объектов.
- Управляемый workspace задаёт `default_agent=plan`. [OpenCode применяет этот default к новым сессиям](https://opencode.ai/v2/docs/agents), а не меняет уже выбранный агент существующего диалога.
- Plan дополнительно запрещает мутации Kubiki, shell и доступ к внешним каталогам. Это локальные настройки выделенного Kubiki workspace; глобальные конфиги пользователя не переписываются. Build остаётся доступен для запрошенных изменений, в пределах MCP policy и подтверждений CLI.
- Короткая workspace-инструкция направляет на `kubiki/diagnose_resource`. При отсутствии инструмента агент должен сообщить о блокировке подключения, а не читать host configs, environment, bootstrap credentials и перебирать сокеты.
- Внешний kickoff сохраняет полное требование к диагнозу, неопределённости, исправлению и проверке; имя встроенного `propose_plan` заменяется обычным планом, поскольку external MCP его не экспортирует.
- Stdio relay дожидается оставшихся ответов после EOF; закрытие сервера не оставляет процесс заблокированным на фоновой stdin-задаче Tokio. Это исправляет отдельный крайний случай коротких диагностических клиентов, а не объясняет отсутствие инструментов в Code Mode.

Глобальные MCP OpenCode всё ещё наследуются. В журнале видна задержка около 25 секунд от не связанного с Kubernetes WordCraft-сервера. Его конфигурация не изменялась; эта задержка отделена от ошибки выбора каталога.

Это сумма повторной передачи контекста по запросам, не размер одного контекстного окна и не денежный счёт. Прерванная последняя генерация может не иметь полного usage.

Главный источник потерь — 22 последовательных шага без диагностики Kubernetes. Контекст вырос почти в 4,7 раза. Сохранённые результаты `execute` занимают около 23 KB сериализованного content, shell — около 13,7 KB; среди крупнейших ответов — каталоги поиска инструментов. Это байты сохранённого content, не независимые фактические token counts каждого инструмента. Prompt/schema/history breakdown этого внешнего запроса не сохранён, поэтому точно распределить input между ними нельзя.

## Flux HelmCharts и остальные CRD

`useCustomResources` ранее выполнял один `getCustomResources` при открытии и повторял его только после ручного Refresh. Настоящей подписки не было. Built-in informer, в свою очередь, принимал только виды из статического реестра.

Теперь CRD-вкладки в desktop используют тот же informer и поток дельт, что встроенные ресурсы. Backend перечитывает определение CRD, проверяет UID и выбирает served version; renderer не задаёт произвольный REST plural. При смене UID/версии возвращается явная ошибка вместо чтения другого API. Reconciler получает действительную namespaced/cluster scope, включая custom kinds с именами, совпадающими со встроенными.

Подписки одного CRD/scope разделяются между панелями. Отмена закрывает также незавершённую авторизацию/discovery; смена context/namespace не принимает старые ответы. Снимок одной namespace не удаляет данные другой закреплённой панели. Dashboard snapshots не перетирают текущие live CRD streams. В браузере без native watch используется обновление снимков.

Исправлен общий механизм CRD, включая `source.toolkit.fluxcd.io/HelmChart`; это не утверждение о проверке всех возможных вкладок на live-кластере.

## Проверка и применение

По просьбе пользователя тесты после уточнения не запускались. TypeScript проверен; Rust проверен компилятором, отладочный `src-tauri/target/debug/kubiki` собран. Live-кластер не изменялся, реальные модельные запросы не выполнялись. Уже запущенный desktop backend нужно перезапустить, чтобы он использовал новый IPC/watch/launcher; существующая сессия OpenCode сохраняет ранее выбранный Build, новый default применяется к новой сессии.
