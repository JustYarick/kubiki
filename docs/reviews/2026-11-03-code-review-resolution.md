# Актуализация спецификаций и документации AI-агента

Дата: 2026-11-03.
Основание: результаты проверки по команде `/code-review` относительно базы `v1.1.1-dev.22`.

В ходе анализа функционала нового агента (модули `crates/kubiki-ai`, `crates/kubiki-tools`,
`crates/kubiki-mcp`, `src-tauri/src/opencode.rs`, `src/domains/ai/`) и сопоставления
с документами проекта были выявлены расхождения между кодовой базой и ранними версиями
спецификаций. Все связанные документы приведены в полное соответствие с текущей реализацией.

---

## 1. Актуализация стандартов (Standards Axis)

| Документ | Раздел / Правило | Внесенные изменения |
| --- | --- | --- |
| `docs/STRUCTURE.md` | AI Domain Tool Execution Boundary | Уточнено описание выполнения инструментов: нативный агент десктопа выполняет инструменты in-process напрямую через `ToolExecutor` / `ToolCatalog` (`kubiki-tools`). Модуль `crates/kubiki-mcp/` предоставляет сервер MCP, CLI `kubiki-mcp serve` и мосты подключений для внешних сред (OpenCode). Задокументированы новые модульные компоненты: `ActionApprovalCard`, `QuestionCard`, `ThinkingBlock`, `CompactToolMessage`. |
| `docs/STRUCTURE.md` | Settings Layout | Отражено разделение стилей настроек: карточная компоновка (`.ai-settings-card`, `.ai-form-line`) используется для комплексных настроек ИИ-провайдеров и политик MCP, оставаясь при этом в едином жизненном цикле модального окна настроек. |
| `docs/LOCAL_STATE.md` | Local Storage & SQLite Persistence | В сводную таблицу и описание добавлен раздел хранения AI-состояния: транскрипты диалогов и полнотекстовый индекс сохраняются в SQLite (`ai/history.sqlite3`), настройки моделей и UI — в `localStorage`, ключи доступа — в нативном хранилище учетных записей ОС (`keyring`). Сессионные токены и стримы в память не сохраняются. |

## 2. Актуализация требований и спецификаций (Spec Axis)

| Документ | Раздел / Требование | Внесенные изменения |
| --- | --- | --- |
| `docs/AI_AGENT.md` | Reasoning & Thought Process Streaming | Добавлена спецификация поддержки потокового вывода рассуждений модели (`<think>` и `<thought>` теги, используемые в DeepSeek-R1, Qwen-2.5 и др.). Описан парсер и динамический анимированный компонент `<ThinkingBlock />`. Зафиксировано строгое разделение: мысли модели носят информационный характер и никогда не интерпретируются как планы (`PlanArtifact`). |
| `docs/AI_AGENT.md` | Workload Verification | Детализирована логика верификации: для стандартных контроллеров (`Deployment`, `StatefulSet`, `DaemonSet`, `ReplicaSet`) требуется совпадение поколения (`observedGeneration`) и числа реплик; для пакетных задач (`Job`) проверяются терминальные условия (`Complete`, `Failed`) или пауза (`suspended`) без требования полей реплик контроллера. |
| `docs/AI_PLAN_CONTRACT.md` | П. 6 — Проверка контроллеров и задач | В контракт верификации внесены явные правила проверки пакетных объектов (`Job`) в отличие от контроллеров с непрерывными репликами. |
| `docs/decisions/007-portable-cluster-tools-and-opencode.md` | Standalone MCP & Resource Links | Синхронизированы пункты о запуске standalone MCP: вызов выполняется напрямую через CLI-утилиту `kubiki-mcp serve`, а для встроенного OpenCode мост подключается автоматически через PTY/runtime. В схемах ответов инструментов зафиксирован возврат канонических идентификаторов ресурсов (`context`, `namespace`, `kind`, `name`) с последующим маппингом на ссылки `kubiki://` в десктоп-клиенте. |

## 3. Рекомендации по оптимизации кода (Code Smells & Bug Prevention)

По итогам статического анализа кода сформированы рекомендации для последующего рефакторинга:

1. **`crates/kubiki-tools/src/kubernetes.rs` (Верификация `Job`):**
   - Учесть, что при вызове `verify_workload` для объекта с `kind == "Job"` поле `generation` контроллера может отсутствовать в квитанции операции. Проверка `generation` должна быть условной (`target.kind != "Job"`).
2. **`crates/kubiki-ai/src/provider.rs` (Repeated Switches):**
   - Вынести протоколо-зависимый код взаимодействия с LLM (OpenAI, Anthropic, Ollama, Responses) в типизированные реализации трейта адаптера протокола вместо каскадных `match protocol`.
3. **`src-tauri/src/opencode.rs` (Primitive Obsession):**
   - Заменить строковую упаковку составных ключей процессов (`format!("{owner}\0{id}")`) на типизированную структуру `LaunchKey`.
4. **`crates/kubiki-tools/src/session.rs` vs `kubernetes.rs`:**
   - Переиспользовать единый хелпер `session::mutation_tool` для проверки мутирующих инструментов.
